## 1. 启动应用

首先，确保应用能够正常启动：

```bash
cd app
npm run dev
```

应用启动后，您应该能看到我们实现的界面，包括侧边栏、内容区域等。

## 2. 测试窗口控制功能

测试窗口标题栏上的控制按钮是否正常工作：

- 点击最小化按钮，窗口应该最小化
- 点击最大化按钮，窗口应该最大化
- 点击关闭按钮，窗口应该关闭（应用退出）

**预期结果**：
- 最小化按钮应该将窗口最小化到任务栏
- 最大化按钮应该将窗口最大化，再次点击应该恢复窗口大小
- 关闭按钮应该关闭窗口并退出应用

## 3. 测试主题切换功能

- 点击侧边栏底部的"切换主题"按钮
- 观察界面是否在浅色/深色/跟随系统之间切换
- 查看控制台输出，应该有"主题已切换为: xxx"的日志

**预期结果**：
- 界面应该在浅色、深色和跟随系统三种模式之间循环切换
- 控制台应该输出当前主题的信息
- 主题设置应该在应用重启后保持

## 4. 测试下载功能

在"下载管理"页面：

1. 在输入框中输入一个有效的视频链接（例如：https://www.bilibili.com/video/BV1xx411c7mD）
2. 点击"开始下载"按钮
3. 观察控制台输出，应该有以下日志：
   - "解析视频链接: xxx"
   - "开始下载: xxx"
   - "下载任务已创建: xxx"
4. 下载任务列表应该显示新创建的任务
5. 随着时间推移，任务的进度应该会更新
6. 最终任务应该完成，并显示"下载完成"的消息

**预期结果**：
- 视频链接应该被成功解析，显示视频信息
- 下载任务应该被创建并显示在任务列表中
- 任务进度应该逐渐增加，最终达到100%
- 任务完成后，状态应该变为"完成"

## 5. 测试设置功能

在"设置"页面：

1. 修改一些设置（例如下载路径、最大同时下载数等）
2. 点击"保存设置"按钮
3. 刷新页面或重启应用
4. 检查设置是否被正确保存

**预期结果**：
- 设置应该被成功保存
- 重启应用后，设置应该保持不变
- 控制台应该显示"设置已保存"的日志

## 6. 查看日志和调试信息

为了更详细地了解IPC通信是否正常工作，您可以：

### 6.1 查看主进程日志

- 在启动应用的终端窗口中，应该能看到主进程的日志输出
- 例如："所有IPC处理器已设置"、"解析视频链接: xxx"等

### 6.2 查看渲染进程日志

- 打开开发者工具（按F12或Ctrl+Shift+I）
- 在Console标签页中，应该能看到渲染进程的日志输出
- 例如："下载进度更新: xxx"、"下载完成: xxx"等

### 6.3 使用开发者工具调试

- 在Network标签页中，可以查看网络请求
- 在Application标签页中，可以查看本地存储（包括设置）
- 在Elements标签页中，可以查看DOM结构

## 7. 测试错误处理

测试错误情况下的行为：

1. 输入无效的视频链接，观察错误处理
   - 预期结果：应该显示错误消息，不会创建下载任务

2. 断开网络连接，测试离线情况下的行为
   - 预期结果：应该显示网络错误消息，提示用户检查网络连接

3. 输入无效的文件路径，观察错误提示
   - 预期结果：应该显示路径无效的错误消息

## 8. 使用控制台手动测试IPC

在渲染进程的开发者工具Console中，您可以手动调用IPC方法进行测试：

```javascript
// 测试ping-pong
window.api.test.ping().then(response => console.log(response))

// 测试获取下载列表
window.electron.ipcRenderer.invoke('download:list').then(tasks => console.log(tasks))

// 测试获取设置
window.electron.ipcRenderer.invoke('settings:get').then(settings => console.log(settings))
```

**预期结果**：
- `window.api.test.ping()`应该返回"pong-async"
- `window.electron.ipcRenderer.invoke('download:list')`应该返回下载任务列表
- `window.electron.ipcRenderer.invoke('settings:get')`应该返回应用设置
